# DEF-003 — Spaces-only customer name bypasses validation

## Classification
Deliberately introduced training defect in QA Demo Shop.

## Status
Reproduced; fix awaiting verification.

## Severity
Medium within this practice application: invalid customer details
can pass checkout validation. No real order processing exists.

## Environment
Local Node.js server, Playwright, Chromium.

## Steps to reproduce
1. Add Wireless Mouse to the cart.
2. Enter three spaces in Full name.
3. Enter tester@example.com as Email.
4. Enter 123 Test Street as Delivery address.
5. Click Place demo order.

## Expected result
Display: Name and address must contain more than spaces.
Prevent submission and preserve the cart.

## Actual result
The validation alert remained empty.
CHECKOUT-004 failed at the validation-message assertion;
later assertions were not reached.

## Automated evidence
Command:
npx playwright test boundaries.spec.js --project=chromium --grep CHECKOUT-004

Observed result:
1 failed; expected the validation message, received an empty string.

Saved report:
evidence/DEF-003/failing-report/index.html

## Root cause
Removing trim() leaves a spaces-only name as a nonempty, truthy string,
so the nonblank-name check does not reject it.

## Proposed fix
Restore trim() before validating the customer name.
